# Lesson Spec

**Status:** Phase B2.
**Scope:** lesson data format, `LessonRunner` contract, narration, checkpoints, and the `quiz_prompt` sentinel. Quiz rendering and progress are Phase B3.

A lesson is **data**. The runner is generic. Adding a lesson means appending an object to a unit's lesson registry; no engine or page-controller edits.

---

## 1. Lesson object

```js
export const bstInsertLesson = {
  id: "bst-insert-basics",            // stable, unique, used as the cache key
  title: "Inserting into a BST",      // shown in the lesson picker
  unit: "bst",                        // id from ALGOLAB_UNITS
  description: "One-line summary shown under the picker (optional).",

  // Exactly one of `ops` or `values` is required.
  ops: [
    { op: "insert", value: 50 },
    { op: "insert", value: 30 },
    { op: "delete", value: 30 }
  ],
  values: [50, 30, 70],               // insert-only shorthand; `ops` wins if both exist

  narration: {
    "0": "Step-index narration wins over type narration.",
    compare: "Used when no index key matches.",
    insert_done: "Falls back to step.annotation, then to an empty string."
  },

  checkpoints: [
    {
      beforeValue: 20,                // relative anchor (see §3)
      op: "insert",                   // optional disambiguator when values repeat
      kind: "predict",                // "predict" | "reveal"
      prompt: "Where will 20 be inserted?",
      choices: ["Left of 30", "Right of 30"], // optional; omit for free-form reveal
      answer: 0,                      // required when `choices` is present
      reveal: "20 < 50 and 20 < 30, so it becomes the left child of 30.",
      onCorrect: "Correct — smaller values go left.",
      onWrong: "Not quite — compare with each ancestor first."
    }
  ],

  quizId: "bstQuiz",                  // stored in B2; resolved by QuizEngine in B3
  emitQuizPrompt: true                // append a synthetic quiz_prompt step
};
```

### Required fields

| Field | Type | Notes |
| --- | --- | --- |
| `id` | string | Unique across the registry. Cache key. |
| `title` | string | Picker label. |
| `unit` | string | Must match a `units.js` id. |
| `ops` or `values` | array | The op log to replay. |

### Optional fields

`description`, `narration`, `checkpoints`, `quizId`, `emitQuizPrompt`, `estimatedSteps`.

## 2. Step building

Lessons do not store steps. Steps are generated by the backend and flattened by a per-unit builder:

```js
buildSteps: async (lesson) => ({ steps, checkpoints })
```

or simply `steps[]` when no checkpoint resolution is needed.

`LessonRunner` calls the builder once per lesson id and caches the result. `loadLesson(lesson, { forceRebuild: true })` bypasses the cache.

The builder must:

1. Walk `lesson.ops` (or `values`) in order.
2. For each op, request that action with a copy of the ops replayed so far.
3. Append the returned `steps` to one flat array.
4. Resolve each checkpoint's relative anchor to an absolute `atStep` (see §3).
5. Append a `quiz_prompt` sentinel when `emitQuizPrompt && quizId`.

Learn state is rebuilt from `ops`, never via inverse operations. `prev()` renders the previous snapshot; it never undoes an action.

### Why flatten?

`PlaybackController` already handles a flat step list with snapshots. Flattening keeps the runner unit-agnostic and lets a lesson span multiple ops (inserts then deletes) in one scrub timeline.

---

## 3. Checkpoint anchors

A checkpoint must resolve to an **absolute 0-based step index** (`atStep`). Data may use a relative anchor instead:

| Anchor | Resolves to | Use for |
| --- | --- | --- |
| `beforeValue: X` | The step immediately before the op whose value is `X`. | "Predict what happens next." |
| `afterValue: X` | The last step of the op whose value is `X`. | "What did we just do?" |
| `atStep: N` | Exactly `N`. | Escape hatch; brittle if step counts change. |

Resolution rules:

- Filter op blocks by `value === X`.
- If `op` is present, keep only blocks whose `action.op === op`.
- Take the **last** matching block (so insert-then-delete of the same value targets the delete).
- `beforeValue` → `max(0, block.start - 1)`; `afterValue` → `block.end`.
- If nothing matches, fall back to the last non-sentinel step and log a dev warning.

`beforeValue`/`afterValue` are preferred because they survive backend annotation changes and new step types.

---

## 4. Narration

Resolution order for each rendered step:

1. `narration[index]` or `narration[String(index)]`
2. `narration[step.type]`
3. `step.annotation` (backend text)
4. `""`

A narration value may be a string or a function `(step, index) => string`. Functions are still data-only (no DOM access).

The runner calls `onAnnotation(text)` on every step. The page pins the text in `#lesson-narration`; `#step-annotation` remains the Play-mode box so the two modes never clobber each other.

---

## 5. Checkpoints

- The runner pauses when forward navigation lands on a checkpoint index. It does **not** pause when the user navigates backward, seeks, or resets.
- Status becomes `checkpoint`; `next()` and `play()` are no-ops until resolved.
- `choices` present → the UI renders buttons that call `answerCheckpoint(i)`.
- No `choices` → the UI renders a Reveal button that calls `revealCheckpoint()`.
- Resolving emits narration feedback (`onCorrect` / `onWrong` / `reveal`) and returns status to `ready`.
- A resolved checkpoint is not re-triggered in the same session unless the lesson is reloaded.
- Checkpoints are mandatory in Learn mode. Play mode is unaffected.

---

## 6. `quiz_prompt` sentinel

If `emitQuizPrompt` is set, the builder appends:

```js
{ type: "quiz_prompt", quizId: lesson.quizId, annotation: "Lesson complete." }
```

When the cursor reaches that step, the runner:

1. Pauses playback.
2. Sets status to `quiz`.
3. Calls `onQuizPrompt(quizId, lesson)`.
4. Stops forward navigation until the lesson is reset.

Fallback: if the final step is reached, the lesson has a `quizId`, and no sentinel exists, the runner fires `onQuizPrompt` once. B3 will replace the placeholder UI with the real quiz.

## 7. `LessonRunner`

```js
const runner = new LessonRunner({
  buildSteps,                 // async (lesson) => { steps, checkpoints } | steps[]
  onStep,                     // (step, index) => render
  onAnnotation,               // (text) => pin narration
  onCheckpoint,               // (checkpoint) => show prompt
  onCheckpointResolved,       // ({ checkpoint, correct, choiceIndex }) => feedback
  onQuizPrompt,               // (quizId, lesson) => show quiz entry point
  onStateChange,              // (state) => enable/disable controls
  onError                     // (error) => surface an error banner
});
```

`runner` owns a `PlaybackController` so it can intercept step changes for checkpoints.

### Public API

| Member | Behavior |
| --- | --- |
| `state` | `{ status, lessonId, cursor, total, checkpoint }` |
| `currentLesson` | The loaded lesson object. |
| `loadLesson(lesson, { forceRebuild })` | Build or reuse steps; seek to 0. |
| `next()` / `prev()` | Step forward/back; forward honors checkpoints. |
| `reset()` | Cancel, seek to 0, clear resolved checkpoints. |
| `play()` / `pause()` | Auto-advance. Play is blocked at a checkpoint or quiz. |
| `seek(i)` | Explicit jump; never triggers a checkpoint. |
| `revealCheckpoint()` | Resolve a free-form checkpoint. |
| `answerCheckpoint(i)` | Resolve a multiple-choice checkpoint. |
| `resolveNarration(step, index)` | Exposed for tests/debug. |

### State machine

```text
idle ──loadLesson──▶ loading ──ok──▶ ready ⇄ playing
                                        │
                                        ├── checkpoint ──resolve──▶ ready
                                        ├── quiz ──────────────────▶ (stops)
                                        ├── done (last step, no quiz)
                                        └── error
```

`prev()`, `seek()`, and `reset()` always return to `ready`.

## 9. Adding a lesson

1. Append an object to `BST_LESSONS` (or the unit's registry).
2. Give it a unique `id`, a `title`, and `ops`/`values`.
3. Add narration keys (optional; backend annotations already read well).
4. Add checkpoints with `beforeValue`/`afterValue` anchors (optional).
5. Set `quizId` + `emitQuizPrompt` when a quiz exists.

No runner or page-controller edits.
